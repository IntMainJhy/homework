# 作业3接口与数据字典

## 统一外壳

所有业务接口沿用 `{ok, data, error:{code,msg}}`。成功的 code/msg 为空字符串；HTTP 失败的 data=null。接口成功不代表业务通过，更不代表人工批准。

所有请求均检查当前回环 Host/Origin；演示头为 X-Demo-Identity: operator。POST 顶层只有 projectId 和 input，input.identity 必须与演示头一致，moduleId/recordId 提供时必须匹配固定范围。拒绝访问发生在来源或日志读取之前。

## 路由

| 路由 | 方法 | 本阶段行为 |
|---|---|---|
| /api/state | GET | 原展示信息新增 reviewOptions：opinions、reasons、maxReasons |
| /api/run | POST | 原有核对；有来源的 review/manual/needs-info 结果先保存草稿，再返回 draftId、draftCreatedAt、reviewRevision=0、localAuditWrites=1 |
| /api/evaluate | POST | 保留原17场景评估；不把评估中的结果存为正式草稿 |
| /api/reviews | GET | 查询最近草稿摘要及当前已验证链头，无查询参数 |
| /api/reviews/history | POST | input 仅允许 identity、moduleId、recordId、draftId，返回完整历史 |
| /api/reviews | POST | 人工提交结构化意见，校验明确确认、意见版本、操作编号和当前来源 |

blocked/degraded 或无来源结果不产生可复核草稿，返回 draftId=null、localAuditWrites=0。审计保存失败时 /api/run 返回统一失败响应，不把未确认保存的草稿显示为成功。

## 意见提交字段

| input 字段 | 类型与约束 |
|---|---|
| identity | 显式 operator，与头一致 |
| moduleId / recordId | 可省略；提供时必须匹配固定范围，空串也拒绝 |
| draftId | 服务端生成的 UUID v4，必须属于本地固定范围日志 |
| expectedRevision | 非负安全整数，即操作者已读取的意见数量 |
| operationId | 客户端生成的 UUID v4，同一次意见重试保持不变 |
| opinion | acknowledged、needs-info 或 escalated |
| reasonCodes | 非空且不重复的白名单数组，最多由配置限定的数量 |
| acknowledgement | 必须为布尔 true，不能是字符串或缺失值 |

禁止 notes、签名、approved、业务写回、客户端时间和任何未知字段。意见保存后仍为 approval=未获人工批准。

| reasonCodes 值 | 中文 |
|---|---|
| evidence-reviewed | 已查看本草稿证据 |
| version-conflict | 版本存在冲突 |
| missing-record | 资料或检查项缺失 |
| open-exception | 仍有未结异常 |
| source-stale | 来源时效需核实 |
| scope-question | 适用范围需人工确认 |

成功保存返回 review、revision、replayed、localAuditWrites、writes=0、externalSends=0 和 approval。重试不会追加新意见，replayed=true 且 localAuditWrites=0。若意见已经保存，即使后来来源不可用，重试返回的仍是历史响应，不能解释为重新核实来源。

## 历史返回字段

| 字段 | 含义 |
|---|---|
| draftId / createdAt | 原草稿编号、服务端创建时间 |
| resultHash / sourceHash | 原领域结果与原始合成来源的 SHA-256 |
| simulation | 当次白名单合成覆盖值，不含任务原文或请求头 |
| revision | 已保存意见数量 |
| reviewStatus | pending 或 opinion-recorded，不是 approved |
| latestOpinion | 最近意见枚举；尚无意见为 null |
| result | 保持原来的领域结果、规则版本及来源快照 |
| reviews | 按版本排列的全部意见，包含前次意见编号 |
| chain | verified、eventCount、headHash；仅表示该次本地链校验 |
| writes / externalSends / approval | 0、0、未获人工批准 |

导出使用相同统一外壳，data 为上述完整历史对象。JSON 不支持注释，因此字段说明集中在本文件。

## JSONL 事件

每行固定为 seq、previousHash、type、createdAt、data、hash 六字段。createdAt 使用服务端 UTC ISO 时间；来源中的固定合成时间保持独立，不与意见提交时间混用。

| 事件 | data 字段 |
|---|---|
| draft-created | draftId、result、resultHash、sourceHash、simulation |
| opinion-recorded | reviewId、draftId、revision、previousReviewId、operationId、reviewer、opinion、reasonCodes、acknowledgement |

previousReviewId 首条为 null，后续必须对应同一草稿上一条意见；全局操作编号不能复用为其他意见。新意见不得修改原 result.status、来源快照、培训状态或异常状态。

## 新增 YAML 配置

| 字段 | 默认值 | 说明 |
|---|---|---|
| review.journalPath | var/review-events.jsonl | 相对 config.yaml，只允许 var 目录下简单 JSONL 文件名 |
| review.maxJournalBytes | 2097152 | 最大2 MiB，正安全整数 |
| review.maxEvents | 1000 | 草稿与意见事件总上限，正安全整数 |
| review.listLimit | 50 | 页面最近草稿摘要数量 |
| review.maxReasons | 3 | 单次原因数量上限 |

日志与短时 .lock 文件按本机文件访问策略保存，新目录0700、新文件0600；不提供下载 URL，不自动归档或删除。所有运行参数仍只在 config.yaml；包版本更新为1.2.0，第三方依赖没有增加。

## 新增错误码

| code | HTTP | 触发及处理 |
|---|---|---|
| HUMAN_ACK_REQUIRED | 400 | 未显式人工确认，重新查看并手动勾选 |
| INVALID_REVIEW | 400 | 字段、编号、意见、原因或版本格式不合法 |
| INVALID_DRAFT | 400 | 试图保存不可复核的结果 |
| DRAFT_NOT_FOUND | 404 | 草稿不存在或无法从当前日志定位 |
| REVISION_CONFLICT | 409 | 已有新意见，人工重新加载后决定 |
| IDEMPOTENCY_CONFLICT | 409 | 同一操作编号绑定了不同内容 |
| DRAFT_STALE | 409 | 来源或规则版本变化，重新运行核对 |
| SOURCE_UNAVAILABLE | 503 | 当前来源不可用，不靠历史快照新增意见 |
| AUDIT_CORRUPT | 503 | 日志破损、链不一致、半行或本运行内已见历史丢失 |
| AUDIT_LIMIT | 503 | 达到字节/事件限额，或日志不是普通文件 |
| AUDIT_BUSY | 503 | 其他实例持锁或遗留锁；不自动删除锁 |
| AUDIT_UNAVAILABLE | 503 | 目录/文件读写失败，不能确认保存成功 |

原 FORBIDDEN、SCOPE_FORBIDDEN、ORIGIN_FORBIDDEN 等错误码不变。不存在记录级 DELETE/PATCH、批准或生产放行接口。
