## 可复现运行

需要Node.js 22及以上，无第三方依赖、无需安装包或配置密钥。进入仓库的`作业2`目录后执行：

```sh
node src/server.mjs
# 浏览器打开 http://127.0.0.1:4180
node --test src/demo.test.mjs
node src/verify.mjs ./work-evidence
```

输出目录参数由使用者指定，生成测试日志与评估JSON；不向真实系统写入。预览服务仅监听127.0.0.1，只提供固定静态文件，不暴露仓库文档或任意路径。

## 实际测试结果

当前源码执行24项Node测试，全部通过、无失败或跳过。场景评估17/17通过，重复5轮完全相同。它们是离线合成规则测试，不是50次真实交接验收，不是模型正确率。

证据：[自动测试日志](../证据/自动测试日志.txt)、[评估结果与各源码SHA-256](../证据/评估结果.json)。指定快照由各源码文件的哈希固定，修改代码后重新生成证据；评估结果本身不参与自身哈希，避免循环引用。

| 测试类 | 覆盖 | 主要失败成本 |
|---|---|---|
| 正常 | 版本相符、检查完整、接收人存在、异常无未结项 | 将“规则通过”误当业务放行 |
| 缺项/边界 | 接收人缺失、培训缺失/未确认、漏记检查项 | 错把不完整包交到下游 |

| 权限 | 未授权、伪造admin、未知记录、跨模块 | 读取其他范围记录 |

## 缺陷修复与未解决项

平台原包使用通用场景预设，仅比较选择的故障类型；本作业改为对合成数据字段执行规则，用户改培训版本、检查项、确认状态、接收人会实际改变核对结果。收紧身份白名单，拒绝任意字符串身份；补未确认与缺失区分、版本有效期、异常和时间标记；增加记录下载；保持原值不可变。

回归范围覆盖全部17场景及7组额外契约/来源/重复检查。真实业务审核意见未取得，业务适用性仍为待评审。已知限制包括：真实系统未连接，身份为客户端演示，只有一个固定样本，没有持久访问审计，没有实际审批、动态多记录关联、超时重试或真实用户反馈。多条数据的重复编号、空时间、单位与版本断链质量检查尚未实现，不能用单条样本测试冒充已解决。

## 受控试点与用户验收计划

范围拟一个批次、四周、两名业务骨干，每周不超过四小时（两人合计/每人口径待顾明岚确认）。演练质量目标来自f02/f42：50次交接全部匹配有效指引版本，未复核异常保留责任人与状态，并能关联来源与人工复核记录。真实名单、授权、样本和签核人尚待确认。

第1周采基线及对照，第2周使用只读规则，第3周验证异常与用户独立操作，第4周按同口径复核工时、返工和确认完整率。样本保持岗位、班次、异常比例可比，操作工时与等待分别记录。若只有50条样本，不能据此推断所有岗位普遍有效。

07-2须找真实使用者林亦舟及接收方，让其独立完成正常、缺项、冲突、故障、拒绝路径，观察卡点并记录时间、反馈和不通过项。代理已验证界面不等于用户已验收。出现越权、自动放行、覆盖原值、漏掉已知关键版本差异任一例即停，由傅景复核。

07-3当前决定：继续课堂原型验证，暂不扩大真实试点；实际价值尚未测量。ROI仅为假设试算，不能归因或宣布客户收益。

## 本地发布与回滚演练

实际在隔离目录复制已验证源码作为已知良好快照；运行正常结果为review；故障注入把指引状态改为unconfirmed，结果变为manual；恢复原文件后重新运行，结果恢复review且源码SHA-256与初始完全一致。[回滚记录](../证据/本地回滚演练.json)保留三个步骤的时间与哈希。这是本地源码回退演练，没有生产部署、客户压力或真实网络故障。

正式发布前应固定经过验收的提交版本，由顾明岚、秦芮、傅景分别给出业务、技术、风险意见；任一方不同意即不发布。灰度仅获授权批次，先只读、可停用。任一关键误判、越权或版本异常，停用草稿并恢复人工流程；维护人恢复已知良好版本、跑正常与冲突样本，再由授权人员确认恢复。生产窗口、值守、具名回滚人、权限及预算均待确认。
