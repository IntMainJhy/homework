# 安装、启动与自测

> 第一阶段文档归档：作业3已新增本地复核记录、配置和接口，当前说明见[作业3方案](../../../作业3/doc/人工复核记录与追溯方案.md)与[接口字典](../../../作业3/doc/接口与数据字典.md)。

需要 Node.js 22 及以上，以及 npm。安装时只从锁文件恢复 yaml；业务运行无需外网、模型密钥或真实企业数据。

## 从仓库根目录启动

```sh
cd 作业2/src # 进入现有源码目录。
npm ci --ignore-scripts --no-audit --no-fund # 精确安装锁定的唯一依赖。
npm start # 启动 YAML 配置指定的本地服务。
```

浏览器打开 [本地工作台](http://127.0.0.1:4180)。如配置修改端口，以启动日志和 YAML 为准；浏览器和命令使用相同端口。服务只接受当前 `127.0.0.1:端口`，不使用 localhost 替代，以匹配 Host 检查。终端按 Ctrl+C 停止。

## 自动测试与可直接运行的验证脚本

在源码目录运行：

```sh
npm test # 运行规则与真实 HTTP 集成测试。
npm run verify # 直接运行 smoke.mjs，自启随机回环端口，完成后自动关闭。
node verify.mjs ../work-evidence/phase1 # 保存本次测试日志、源码哈希和五轮评估证据。
```

`npm run verify` 不要求先启动服务，不会连接用户已运行的 4180 服务；它验证当前磁盘源码。端口 0 只用于隔离测试，日常 npm start 的端口只从 YAML 读取。

在仓库根目录也可一次执行：

```sh
npm --prefix 作业2/src ci --ignore-scripts --no-audit --no-fund # 安装精确依赖。
npm --prefix 作业2/src test # 执行全量测试。
node 作业2/src/smoke.mjs # 直接运行完整 HTTP 验证脚本。
node 作业2/src/verify.mjs 作业2/work-evidence/phase1 # 输出到新证据目录。
```

smoke 成功摘要应包含 `ok=true`、`checked=19`、`evaluation=17/17`、`sourceUnchanged=true`。任何断言失败时退出非零，并关闭临时服务。证据脚本的测试数量从 TAP 动态读取，不硬编码原来的 24/24。

## 页面自测步骤

| 操作 | 预期 |
|---|---|
| 初次打开 | 尚未运行，不显示默认成功结论 |
| 默认 operator 输入，运行核对 | review，待人工复核，人工批准为零 |
| 培训版本改 v1，运行 | manual，提示版本冲突 |
| 恢复 v2，检查项改 C01 | needs-info，提示 C02 未记录 |
| 培训改为尚未确认 | manual，不将记录存在算作培训完成 |
| 接收人清空 | needs-info，不自动补接收人 |
| 演示身份改为未授权访客 | HTTP 403，清除旧结果，不显示本次来源 |
| 正常运行后导出 | 下载统一结构 JSON，原始合成来源版本与时间保留 |
| 点击场景评估并运行 | 实际 17/17，不代表真实客户验收 |

## 请求运行中的服务

以下命令需另一个终端已运行 npm start；如更改端口，请同步改地址。

```sh
curl --fail-with-body -sS http://127.0.0.1:4180/api/run -H 'X-Demo-Identity: operator' -H 'Content-Type: application/json' --data '{"projectId":"fsg-production-handover","input":{"identity":"operator","moduleId":"fsg-production-handover","recordId":"HND-DEMO-001","trainingVersion":"v1"}}' # 应返回 ok=true 且 data.status=manual。
curl -sS http://127.0.0.1:4180/api/state # 无身份头，应返回 403 和 data=null。
curl -sS http://127.0.0.1:4180/config.yaml # 应返回 404，配置不得公开。
```

## 失败与恢复

| 现象 | 处理 |
|---|---|
| 找不到 yaml 包 | 在 src 执行 npm ci，使用 package-lock.json |
| 配置错误，服务未启动 | 检查 YAML 缩进、重复键、类型及固定范围；不删除配置以求回退 |
| 端口被占用 | 停止自己的旧服务或修改 server.port 后重启，不结束无关进程 |
| 页面报 403 | 使用 127.0.0.1 和正确端口；检查演示头、identity 及范围是否一致 |
| 初始化返回 503 | 检查 data/handover.json 是否存在、合法且满足合成数据契约 |
| 核对结果 degraded | 检查来源文件，修复后重新运行，不将历史结果当作当前有效结论 |
| 核对结果 manual | 按差异补证或转人工，不能修改规则绕过安全检查 |
| 刷新后轨迹消失 | 当前只在内存保留；刷新前下载结果，不把下载当持久审计 |

## 验证边界

所有用例都使用合成数据。首次安装依赖需要访问 npm；服务、测试和验证只访问本机。没有执行真实员工培训、设备操作、真实系统集成、客户 UAT、生产发布或正式人工签字。

历史 `docs/证据` 保留原版本结果；本阶段新证据写入 work-evidence，避免覆盖原资料。输出目录不能位于 src 或 docs 中。
